## 1. 口径：54 + 4 = 58

两个官方数字一直对不上，差别就在**有轨电车**：

| 来源 | 口径 | 城市 | 线路 | 里程 |
| --- | --- | --- | --- | --- |
| 中国城市轨道交通协会，2024-12-31 | 含与社会车辆混行的**有轨电车** | **58** | 361 | 12,160.77 km |
| 交通运输部，2025-12-31 | 排除混行有轨电车 | **54** | 343 | 11,710.3 km |

用户决策 **D3：排除有轨电车**。所以本项目：

- **主线 54 城**建页 —— 地铁、轻轨、跨座式单轨、自动旅客捷运、磁浮、市域（郊）铁路；
- **另有 4 座「只有有轨电车」的城市**登记为 `excluded_tram`，不建页：淮安、天水、三亚、文山；
- 54 + 4 = 58，与协会口径的城市数对齐，任何一方问起来都能对上账。

有轨电车与地铁共城的（沈阳、大连、长春、青岛、深圳、广州、武汉、南京、苏州、嘉兴、佛山、珠海…）**只排除有轨线路本身**，该城的地铁页照建。

**为什么保留它们在台账里**：它们确实是「有城市轨道交通服务的城市」，写进台账可以解释 54 这个数怎么来的；但建页会得到一个只有一条线、地图几乎空白的页面，不如在邻市页里用跨城字段表达。

最终按 0.2/0.3 的 OSM 关系数确认：若某城自身关系数 ≥ 1 条独立线网，仍单独建页。

## 5. 与公开口径不一致的已知点

台账里的 `lines_public` 对已完成城市填的是**本站现状**，所以和维基数不同：

| 城市 | 维基 | 本站 | 原因 |
| --- | --- | --- | --- |
| 上海 | 21 | **20** | 本站不含市域机场线（按 §2 范围边界，市域铁路不进主线） |
| 成都 | 17 | **16** | 本站不含资阳线 S3（跨市线，归成都但单独统计） |
| 合肥 | 7 | **8** | 本站含 5 号线北段，维基按整线计 |

这三处不是错误，是口径差异，写在这里备查，避免后面批次被人当成 bug 追。

### 8.2 admin id

新增 `pipeline/18_admin_ids.py`，一次扫描产出 `data/admin-ids.json`（142 KB，28 省）：

- `l4` = 省级面，`l5` = **地级市面**，`l6` = 区县面 —— OSM 中国行政层级和直觉不同，**地级市是 `admin_level=5`**，第一版按 6 收导致 49 城匹配失败；
- 部分省面名称带民族文字后缀（`新疆维吾尔自治区 شىنجاڭ…`、`内蒙古自治区 ᠦᠪᠦᠷ…`），按前缀建索引才对上；
- 自治州名称（`文山壮族苗族自治州`）需要「前缀 + 级别优先」的兜底匹配。

结果：**58/58 城两列 id 全部回填**（`city_admin_id` 与 `province_admin_id`），直辖市两列同值。

### 8.3 每城关系数与工作量

按 `network` 标签统计关系数（一个官方线通常是 2 条关系 —— 上下行，交路再多几条）：

| 城市 | 线路关系 | 其中 subway | light_rail | monorail |
| --- | --- | --- | --- | --- |
| 广州 ✓ | 81 | 73 | 8 | 0 |
| 北京 | 60 | 56 | 2 | 2 |
| 上海 ✓ | 52 | 48 | 4 | 0 |
| 深圳 | 45 | 42 | 3 | 0 |
| 成都 ✓ | 42 | 42 | 0 | 0 |
| 重庆 | 36 | 28 | 0 | 8 |
| 杭州 | 32 | 32 | 0 | 0 |
| 南京 | 31 | 27 | 4 | 0 |
| 天津 | 28 | 28 | 0 | 0 |
| 武汉 / 西安 | 26 | 26 / 24 | 0 / 2 | 0 |
| 苏州 | 24 | 24 | 0 | 0 |
| 合肥 ✓ | 18 | 18 | 0 | 0 |

已完成四城合计 **193 条关系**，待做 50 城合计 **510 条**。

用 P1a 实测（广州 81 关系 ≈3.5 人天、成都 42 ≈3、合肥 18 ≈1.3）拟合，**手工模式**近似：

```
人天 ≈ 0.9 + 0.035 × 关系数
```

按这个式子，50 城手工全做 ≈ **63 人天**；方案 C 的目标是 ≈40 人天（0.8 天/城），也就是说**自动化必须把单城人工压掉约 35%**，这正是阶段 2 三件套（自动映射、自动合并、自动校验）要拿到的收益。

### 8.4 一个必须先解决的问题

`network` 标签**覆盖不全**：`(无 network)` 桶里有 15 条 subway + 13 条 light_rail，导致 **15 城完全取不到关系数**：镇江、金华、资阳、鄂州、湘潭、许昌、咸阳、哈尔滨、厦门、贵阳、乌鲁木齐、兰州、芜湖、马鞍山、文山。

结论：**归属必须以几何为准**（就是 P1a 的 `05_attribution.py` 那套），`network` 只能当辅助信号。阶段 2 的自动化不能建立在 network 标签上。
